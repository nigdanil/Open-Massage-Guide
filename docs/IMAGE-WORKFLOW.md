# Open Massage Guide — IMAGE WORKFLOW v1

Статус: `working draft`

Документ описывает практический workflow производства изображений для проекта **Open Massage Guide**.

---

## 1. Общий принцип

Работа идёт по карточкам и пакетам.

Каждая карточка проходит один и тот же цикл:

1. выбрать карточку;
2. прочитать `meta.json`, `ru.json`, `en.json`;
3. подготовить промпт;
4. сгенерировать черновик;
5. проверить качество;
6. при необходимости исправить;
7. сохранить итог как `.webp`;
8. положить файл в каталог проекта;
9. обновить `meta.json`;
10. выполнить проверку и commit.

---

## 2. Базовый порядок работы

### Шаг 1. Выбор карточки

Пример:

- `back-001`

Нужно проверить:

- название техники;
- целевую зону;
- тип движения;
- уровень давления;
- направление движения;
- нет ли особых ограничений.

---

### Шаг 2. Подготовка image prompt

Промпт должен описывать:

- анатомическую область;
- положение человека;
- положение рук;
- траекторию движения;
- стрелки;
- единый стиль проекта;
- отсутствие текста в изображении;
- вертикальный формат 4:5.

---

### Шаг 3. Генерация черновика

Результат считается черновиком, если нужно проверить:

- анатомию;
- руки;
- читаемость;
- композицию;
- соответствие технике.

Если есть дефекты, выполняется перегенерация или правка.

---

### Шаг 4. Проверка качества

Проверяем:

- соответствует ли картинка технике;
- правильная ли зона контакта;
- корректны ли руки;
- понятны ли стрелки;
- нет ли визуального мусора;
- нет ли текста;
- выдержан ли единый стиль.

---

### Шаг 5. Сохранение финала

Финальный файл:

- сохраняется как `.webp`;
- получает имя по `id` карточки;
- кладётся в правильную папку.

Пример:

```text
assets/images/techniques/back/back-001.webp
```

---

### Шаг 6. Обновление `meta.json`

До:

```json
{
  "image": null,
  "status": "draft"
}
```

После:

```json
{
  "image": "./assets/images/techniques/back/back-001.webp",
  "status": "published"
}
```

---

### Шаг 7. Проверка и commit

После добавления изображения:

```bash
node scripts/validate-content.mjs
```

Затем:

```bash
git add .
git commit -m "feat: add image for back-001"
git push
```

Если добавлялся пакет:

```bash
git add .
git commit -m "feat: add pilot back technique images"
git push
```

## 4. Naming convention

### Изображения

```text
<category>/<id>.webp
```

Примеры:

```text
back/back-001.webp
neck-shoulders/neck-005.webp
arms/arms-003.webp
```

### Commit messages

Одна карточка:

```text
feat: add image for back-001
```

Пакет:

```text
feat: add back technique images 001-012
```

Пилот:

```text
feat: add pilot back technique images
```

---

## 5. Рекомендации по качеству WebP

Если конвертация делается отдельно:

- формат: `webp`
- качество: `80`
- если файл слишком тяжёлый — пробовать `78`, `76`, `75`
- если появились артефакты — поднять до `82–85`

Главный принцип:

- визуально чисто;
- вес без перегруза;
- детали рук и стрелок не должны разваливаться.

## 6. Мини-чеклист перед публикацией

- [ ] правильный каталог
- [ ] имя файла совпадает с `id`
- [ ] `webp`
- [ ] изображение вертикальное
- [ ] без текста
- [ ] зона понятна
- [ ] руки корректны
- [ ] стрелки логичны
- [ ] обновлён `meta.json`
- [ ] `status = published`
- [ ] проверка проекта прошла успешно

---

## 7. Что делать, если изображение неудачное

Если проблема в анатомии или композиции:

1. не публиковать;
2. сделать ещё одну генерацию;
3. уточнить промпт;
4. отдельно усилить ограничения по рукам, положению и стрелкам.

Если проблема только в весе файла:

1. сохранить финал;
2. сконвертировать в WebP с меньшим quality;
3. проверить визуально ещё раз.

---

## 8. Долгосрочная стратегия

Работать маленькими стабильными пакетами.

Оптимально:

- 3 пилотных изображения;
- затем 10–12 изображений одной категории;
- commit;
- проверка в PWA;
- переход к следующей категории.

Это лучше, чем пытаться делать весь каталог за один раз.
